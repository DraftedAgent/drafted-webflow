# Initial hero — local candidate, not published

The published Webflow response still contains the legacy heading. Publishing only JS/CSS cannot remove that first-paint content. This candidate must ship with a replacement of the actual Home markup and its head content.

Generated by `node tools/build-initial-hero.cjs` from the approved SVG assets, geometry, scoped hero CSS and the two small hero modules:

- `head.html`: critical first-viewport CSS, the early motion eligibility/failure watchdog and independent hero runtime. Insert before editor/vendor loading. The runtime observes the parsed ready marker, not DOMContentLoaded or window load.
- `hero.html`: the complete response fragment. It replaces the original navbar and hero, inside `.page-scroll` before `#section-input`. It contains the static navigation wordmark, correct heading/description/CTA, final fallback vectors, exact solid initial SVG and in-response geometry.
- `hero-visual.html` and `motion-data-1.html`/`motion-data-2.html`: balanced visual/data fragments if the editing surface needs separate slots. Each data part is bounded; the ready marker belongs after the last part. `motion-data.html` combines them for file-based integration. Do not add these alongside the complete fragment.
- `drafted-hero.js` at repository root: the same standalone runtime for inspection; the generated head embeds it so a cold first paint does not wait for an extra script request.

The geometry's prefix deltas reconstruct every approved vector path string exactly. There is no native streamed decoder or external geometry/image/font fetch on the hero's start path. Text and CTA exist directly in the response. The entire brand/content group reserves its two grid rows before child markup finishes parsing. No hero content is hidden behind a loader.

With no JavaScript, reduced motion, missing capabilities, corrupt data or a failed early runtime, the static final logo remains available. A head watchdog settles an uninitialized start after five seconds and prevents any later jump back to the start. Once initialized, visibility starts the 2400ms sequence once; later editor initialization only adopts the existing nodes.

## Prepared deployment change

1. Replace the actual old Home navbar/hero elements. The legacy heading must be absent from the exported response, not hidden or deleted after load.
2. Install the generated head and visual/data fragments once, with the same selectors/IDs as the preview. Keep `#section-input` and the rest of the existing editor components.
3. Keep noncritical editor styles/scripts off the first-paint path. The prepared full HTML uses nonblocking styles with a no-JS stylesheet fallback. No new application framework or server-side router is introduced.
4. Deliver the matching editor bundle, which no longer contains or rebuilds the hero, together with the HTML changes. Do not publish this asset-only against the currently old Webflow markup.
5. Inspect current Webflow access, capture the required before-state and test the real candidate before any separately authorized publication. No Designer/page/head setting was modified in this local task.

The same transform can prepare a full current Webflow export:

`node tools/build-initial-hero.cjs input.html output.html`

It refuses output containing the old heading. The localhost `/initial-site` preview serves that prepared current-public shell with local synthetic Drafted endpoints. Cold-cache throttled recordings, DOM/layout audits and failure checks are under ignored `output/pdf/initial-hero/`.
