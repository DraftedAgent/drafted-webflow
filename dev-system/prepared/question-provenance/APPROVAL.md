# Question provenance — proposed backend extension, not deployed

Current data: plan topics include question and signalRefs; Session stores both in the round. Coverage catalog contains jobRef hashes and exact per-signal adEvidence. Neither topic nor persisted question stores a rationale or direct/indirect classification. UI can therefore show verified quotations and recorded signal association, but cannot truthfully state why or label directness for existing questions.

Concrete candidate: add topic.questionLinks, one item per existing signalRef: {ref:{field,index},relation:"direct"|"indirect",explanation:string}. Build discovery prompt must request a short reason at generation time and explicitly classify exploratory/broader links as indirect. Validate model response must enforce exact ref membership/completeness/uniqueness, relation enum and bounded nonempty explanation (max600chars). Existing signalTopics assignment/materialization remains owner of refs; exact quotations continue to come from the validated catalog, not the explanation. Frontend contract, client validator and Session queue must preserve questionLinks as advisory generated metadata associated with question/context revision. No migration may manufacture metadata for historical questions. Focused coverage questions and followups need their own recorded rationale or explicit unavailable state; never reuse a different question rationale.

This requires an explicitly versioned discovery contract extension and review of exact active n8n node definitions before mutation. No active workflow was changed or read as a deployment target in this task. No extra AI operation is required if included in the existing planning response, but it adds response tokens to that existing call. No paid quality test performed. Approval of this document alone must not be inferred; deploy/activate and paid tests remain separate scopes.

Local current UI: quotations only when the entire catalog validates against active ad and signals, question context carries same ad text, and its refs resolve. Legacy questions without ad version show unavailable provenance. Native details preserves textarea/drafts. View in job description reuses existing read-only modal, exact offset/quote check, Close/Escape and return focus. Prototype direct/indirect examples are explicitly synthetic getQuestionSources inputs to the same UI component, not backend capabilities.
