## Local fix

The shared renderer recognizes explicit Name/Professional headline/Contact details labels (with narrowly enumerated Swedish aliases) on existing otherSections/block entries. It displays their text unchanged as primary name, lower-weight headline and contact/link text. It does not parse a name from cvTitle/email/filename/summary, impose three topics, invent missing values or filter CV text. Legacy title-only documents keep the existing string as a secondary document label; it is not asserted to be a person's name. A document with explicit name/contact but no source headline does not promote an ambiguous document label into a new headline.

New uploads always replace documentTitle, including an empty incoming title, so a second CV cannot inherit the previous person's title. Name/contact stay in canonical blocks, existing snapshots/selection/editing/IDs and Apply behavior; no optional personalInfo top-level API field or separate export model is introduced. Browser print continues cloning the same paginated DOM/styles/fonts. Legacy server Export PDF (Classic) builder/handler remains unchanged; its old separate template is not claimed to match this header.

The backend need was explained to the owner before preparing any local backend code. cv-upload-source-guard.cjs is a pure integration candidate, not installed in n8n. It copies existing parser fullName/currentTitle/location/email/phone/otherContacts into existing canonical otherSections text blocks with stable slot IDs. No model call or rewriting is used. Original body blocks/IDs/unknown fields remain. Header collisions fail rather than overwrite facts.

The source guard repairs only standalone model-added bullet markers absent in the linked source and the exact full-line reported parser diagnostic when employer/title really are blank, period matches canonical dates and the diagnostic is absent from that authoritative source record. It requires a known canonical-block-to-parser mapping. Missing provenance, other notes, ordinary parentheses, source-authored markers/diagnostics and mismatched metadata are preserved. Nothing is filtered by the renderer. This addresses the canonical acceptance of model-only non-CV output without a broad parentheses/text cleanup rule.

cv-upload-header-integration.cjs prepares a minimal local patch for EnsureBlocksAndJoin and EnsureBlocksAndJoin1 before rewrittenCv is derived, using their existing expMap mapping. It refuses changed/unrecognized source and repeated installation. BuildResponse and API schema stay unchanged because facts travel in existing canonical blocks. tools/verify-header-upload-node.cjs executed isolated in-memory copies of the actual current SV/EN Code nodes with synthetic input: source facts retained, existing body IDs unchanged, exact artefacts repaired, missing facts not invented. This is local JavaScript verification, not an n8n Cloud execution or model run.
